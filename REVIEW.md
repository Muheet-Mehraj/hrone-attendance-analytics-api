# REVIEW.md

| # | Where (function / area) | What is wrong | How you'd notice it (test, input, or symptom) | How it is fixed in the submitted version |
|---|---|---|---|---|
| 1 | MongoClient configuration | The starter silently falls back to hard-coded connection/database settings instead of requiring the injected configuration. | Start with configuration missing or set different `MONGO_URI` / `MONGO_DB` values and inspect which database is used. | Load `.env` without overriding the real environment and require both variables to be configured. |
| 2 | `/health` | It always returns `200`, even when MongoDB cannot answer a ping. | Stop MongoDB and request `/health`. | Ping MongoDB and return `503` until the database and indexes are ready. |
| 3 | Startup / indexes | No application indexes are created. The check-then-insert pattern therefore has no database uniqueness guarantee and list/analytics queries can scan large collections. | Start against an empty-index database; race two creates or inspect query plans. | Create named, idempotent unique and query-supporting indexes at startup. |
| 4 | `create_employee` | Checking for an existing code and inserting are two separate operations; parallel requests can both pass the check. There is no unique index to arbitrate the race. | Send parallel `POST /employees` calls with the same `emp_code`. | Use a unique index and map `DuplicateKeyError` to `409`. |
| 5 | `EmployeeIn` / `create_employee` | Employee codes, emails, dates and shift rules are weakly validated; equal `shift_start` / `shift_end` is accepted. | Send a malformed employee body or a shift with identical endpoints. | Add schema validation, real calendar-date validation and a cross-field shift check. |
| 6 | `create_employee` | `created_at` is a naive local `datetime`, not a UTC BSON instant normalized to whole seconds; response also returns a datetime instead of epoch milliseconds. | Compare the API value across time zones or inspect the response type. | Store UTC-aware, second-truncated instants and serialize every instant as epoch milliseconds. |
| 7 | `list_employees` | `skip = page * page_size` skips the first page when `page=1`. | Request page 1 and compare it with the first sorted employees. | Use `(page - 1) * page_size` with bounded pagination. |
| 8 | `list_employees` | `total` counts all employees, ignoring a supplied department filter; results are not sorted by `emp_code`. | Filter a department with fewer employees than the full collection and inspect `total` / ordering. | Count the filtered query and sort by `emp_code` ascending. |
| 9 | `compute_late_minutes` | It floors elapsed time to whole minutes before applying the grace-period check. A punch at 09:40:01 for a 09:30 shift is incorrectly treated as not late. | Test 09:40:00 and 09:40:01 against a 09:30 shift. | Compare elapsed seconds to 600 first, then floor whole elapsed minutes. |
| 10 | `compute_late_minutes` | It does not model the full IST/overnight attendance-date rule, and the starter's naive timestamp conversion depends on the host's local time zone. | Test timestamps around midnight for a 22:00–06:00 shift, or run on a non-IST host. | Convert epoch milliseconds through UTC and IST explicitly, assign the attendance date using the overnight rule, and calculate against that shift's start. |
| 11 | `compute_work_hours` | Python's built-in `round` uses ties-to-even rather than the required decimal half-up rule. | Test a duration whose hour value is exactly halfway at two decimal places. | Use `Decimal` with `ROUND_HALF_UP`. |
| 12 | `compute_overtime` | It places every shift end on the attendance date, which is wrong for overnight shifts; it also constructs an IST-aware end while the starter punch timestamps are naive. | Use a 22:00–06:00 shift and punch out the next morning. | Build shift-end on the next day for overnight shifts and compare normalized UTC instants. |
| 13 | `punch_in` | Unknown employees are dereferenced rather than returned as `404`; a check-then-insert race can create duplicate daily records. | Punch in an unknown code, or send parallel requests for the same employee/date. | Check for an employee and rely on the unique (`emp_code`, `date`) index to guarantee one winner (`201`, others `409`). |
| 14 | `punch_in` | `datetime.fromtimestamp()` uses the host local zone, the date is taken from that local timestamp, and overnight shifts are not assigned to their shift-start date. | Punch in near midnight from a server configured to UTC or test an overnight shift. | Normalize/truncate the instant, convert to IST, and apply rule R1 before writing the date. |
| 15 | `PunchInIn` | `status` is an unrestricted string, so `ABSENT` and `LEAVE` can be created through punch-in despite the contract forbidding that. | Submit `{"status":"ABSENT"}` to punch-in. | Restrict punch-in status to `PRESENT`, `WFH` or `ON_DUTY`. |
| 16 | `list_attendance` | It fetches every matching record into Python, sorts and paginates in memory, making it scale poorly and not using the required indexed sort. | Run against 100,000 records or examine the database query. | Use database-side sort, skip, limit and `count_documents` over the filtered query. |
| 17 | `list_attendance` | It orders only by date, so records with the same date have no required `emp_code` tie-breaker; it also adds an extra `id` field that is not in the API contract. | Seed multiple employees on one date and compare the response fields/order. | Sort by date descending then employee code ascending, and serialize only the contracted fields. |
| 18 | `list_attendance` / query parameters | Date format, `date_from <= date_to`, page bounds and page-size maximum are not validated. | Send a reversed date range, malformed date, page 0 or page size 101. | Validate ISO dates, range ordering and the R10 pagination limits, returning `422`. |

## Checked and considered acceptable

- `load_dotenv()` uses its default non-overriding behavior, so pre-existing environment variables take precedence over `.env` values.
- The starter removes MongoDB `_id` from employee create/list responses; the contract also requires removing the replacement `id` field from attendance responses.
- The TODO endpoints are deliberate Part B work, rather than defects in the starter's existing implementations.
